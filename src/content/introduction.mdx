## What Schema-Watch does

A backend changes `id` from a string to a number. Nothing throws, the build is
green, and the first sign of trouble is a broken screen in production.
Schema-Watch closes that gap.

It runs as a local reverse proxy between your frontend and your API. Every
request and response that passes through is reduced to its **shape**: field
names, types, nullability, and whether a field is required. When a shape
changes, Schema-Watch grades the change and shows it on a live dashboard. In
CI, the same comparison runs against a committed baseline and fails the build
on a breaking change.

```console
BREAKING  GET /api/users/:id (response)
    id: string → number
    email was removed (was string)
    affects: web/src/user.js

Breaking API contract changes detected.
```

## Who it is for

- **Frontend engineers** who consume an API they do not control and want to
  know the moment its contract drifts.
- **Backend engineers** who want proof that a refactor did not change a
  response shape that callers depend on.
- **Teams** who want a required pull request check that blocks contract breaks
  without writing or maintaining an OpenAPI specification by hand.

## What it catches

| Change | Example | Typical verdict |
| --- | --- | --- |
| Field type changed | `total: number → string` | Breaking |
| Field removed | `email` no longer returned | Breaking |
| Nullability changed | `user: object → null` | Breaking |
| Optional field became required | request body now needs `currency` | Breaking for requests |
| Array item shape changed | `items[].price` changed type | Breaking |
| Field added | `items[].archived` added to a response | Info (safe) |

Severity depends on direction. A newly required field breaks a **request**
body, because existing callers do not send it, but is harmless in a
**response**.

<Info>
  Schema-Watch compares shapes, not values. Timestamps, IDs, and counts change
  on every request without raising an alert, so every alert means the
  contract actually changed.
</Info>

## Requirements

Schema-Watch is a Node.js CLI published to npm as `schema-watch`. It needs
**Node.js 22.5 or newer**, because it stores captured contracts in the
built-in `node:sqlite` module. No account is required, and nothing leaves your
machine unless you opt in to the hosted service.
